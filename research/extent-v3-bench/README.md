# V3 exact-C engine benchmark

This directory contains a rootless research benchmark that links the exact
production files kernel/extent-v3/codec.c, authority.c, and engine.c. Its
lower adapter is a deterministic in-memory byte array. It does not load a
module, access a block device, implement V2.2, or measure hardware latency or
flash endurance.

Build and run the finite-window matrix:

~~~sh
cc -std=c11 -O2 -g -Wall -Wextra -Werror \
  -I kernel/extent-v3 research/extent-v3-bench/engine-bench.c \
  kernel/extent-v3/engine.c kernel/extent-v3/authority.c \
  kernel/extent-v3/codec.c -llz4 -o /tmp/sv3-engine-bench

mkdir -p /tmp/sv3-engine-artifacts/inputs
/tmp/sv3-engine-bench --synthetic --reps 10 --warmups 2 \
  --seed 12345 --artifact-dir /tmp/sv3-engine-artifacts/inputs \
  > /tmp/sv3-engine-artifacts/engine-runs.jsonl
python3 research/extent-v3-bench/summarize.py \
  --input /tmp/sv3-engine-artifacts/engine-runs.jsonl \
  --output-prefix /tmp/sv3-engine-artifacts/engine
~~~

The matrix includes uniform 2,072 B and 1,048 B opaque payloads, clustered
and alternating 2,200/1,600 B payloads, a six-size wide mix, a 16-record
control, and 3,072 hot/cold updates. Window sizes are 8, 16, 32, and 64
records. Every engine write is an actual sv3_engine_write_window() call;
reads use sv3_engine_read_page(). Setup and allocation are outside the
timed function windows. The ordered4_model columns are a geometry-only
model of V2.2's 8 B header and 8 B descriptor in each 4 KiB container, with
the same ordered records and per-window flush boundaries.

Generate real LZ4 blocks from deterministic 4 KiB source pages and verify
independent decompression plus V3 payload readback:

~~~sh
/tmp/sv3-engine-bench --lz4 --reps 10 --warmups 2 --seed 12345 \
  --artifact-dir /tmp/sv3-engine-artifacts/lz4 \
  > /tmp/sv3-engine-artifacts/lz4-runs.jsonl
~~~

The compressor is LZ4_compress_fast() with acceleration 1 and a 3,568 B
output limit. Target lengths are generated by a seeded random prefix followed
by zeros; the output reports measured lengths, never the requested lengths.
Raw fallback is separately tested and reports the current engine's
-EOPNOTSUPP behavior. This does not integrate compression or raw-page
fallback into the V3 engine.

The fault and randomized checks use:

~~~sh
/tmp/sv3-engine-bench --faults
/tmp/sv3-engine-bench --randomized --cases 2048 --seed 12345
~~~

The fault mode distinguishes physical blocks copied by the adapter from
validated completion counts and authoritative mappings. A silent post-write
payload corruption is published after the callback reports success and is
then detected as -EBADMSG on read; the prototype has no read-after-write
verification. Randomized cases use a deterministic latest-value oracle and
repeat a logical slot every third generated operation.

All byte reductions are in-memory V3-engine results versus modeled V2.2
geometry. Software timing distributions are not loaded-kernel or device
measurements. There is no production V3 Device Mapper adapter, asynchronous
BIO path, real LZ4 integration, raw fallback, segment GC, or reclaim result.
