# V2.2 optional size-aware NBD benchmark backend

## Purpose

The default V2.2 performance script uses memory-backed Linux null_blk. Its
50 Hz `mbps` throttle uses a fixed per-tick byte budget. At 20 MiB/s it can
permanently requeue writes larger than ~409.6 KiB, and an optional whole-segment
1 MiB GC DISCARD can hit the same limit. This does NOT model a real device's
size-proportional transfer time.

An optional userspace NBD backend is now available. It is a **prototype** until
the Linux 7.0.x host smoke test and rate calibration pass.

Files:

- `tests/runtime/size-aware-nbd.py`: sparse RAM disk and NBD transmission server
- `tests/runtime/streaming-benchmark.sh`: opt-in benchmark selection
- `tests/runtime/streaming-benchmark-teardown.sh`: safe dependency-ordered removal
- `tests/runtime/size-aware-nbd-teardown-test.sh`: source-only busy-teardown regression

## Timing and storage model

Each NBD request is processed serially by one userspace server thread,
representing lower queue depth one. Read and write service duration is:

```text
duration_s = command_latency_us / 1_000_000
           + request_bytes / (bandwidth_MiB_per_s * 1_048_576)
```

Unlike null_blk `mbps`, a 512 KiB or 1 MiB request does not have to fit into a
per-tick credit bucket. At 20 MiB/s, the ideal 1 MiB data transfer consumes
50 ms, plus the configured command latency.

The server uses a sparse in-memory dictionary of 4 KiB blocks and implements
NBD READ, WRITE, FLUSH and optionally TRIM. By default TRIM/DISCARD is not
advertised. WRITE FUA is acknowledged only after the RAM simulation operation,
NOT after durable storage: the backend is intentionally volatile.

Python/socket overhead is real. The timing model provides an upper bound on
throughput and must be calibrated against a raw NBD control workload. It is not
a physical storage qualification and cannot predict firmware or FTL behavior.

The revised `selftest` checks 4 KiB and 1 MiB transfer-duration scaling,
full 1 MiB WRITE and READ across a socketpair, FLUSH, enabled TRIM across the
wire, rejection of disabled TRIM and malformed frames, short replies, EOF,
finite client timeouts, partial-write reply framing, and rootless mocked NBD
shutdown errors. It also rejects bandwidth configurations whose worst-case
8 MiB transfer would exceed the 120-second NBD kernel timeout safety margin.
It does not load kernel modules, open devices, or require root.

## Stage 2: dedicated virtual Linux NBD smoke gate

**Only after source-only tests pass**, the operator/tester may use an unused
**virtual** `/dev/nbdN` node. It must be a device created by the kernel NBD
driver, NOT an HDD/SSD/USB/SD disk. Do not select a physical device or change
active system swap.

Prerequisites: the kernel NBD driver is available and an unused device node
already exists. Inspect `lsblk`, `/proc/swaps`, the NBD sysfs PID, holders,
and mounts. The Python backend refuses mounted/active/held NBD devices.

Example, after verifying `/dev/nbd0` is unused and safe:

```bash
sudo env \
  SWAPZ_BENCH_BACKEND=nbd \
  SWAPZ_BENCH_NBD_DEVICE=/dev/nbd0 \
  SWAPZ_BENCH_MBPS=20 \
  SWAPZ_BENCH_LATENCY_NS=500000 \
  SWAPZ_BENCH_DISCARD=0 \
  SWAPZ_BENCH_RUNTIME=2 \
  SWAPZ_BENCH_STRATEGIES="immediate opportunistic staged" \
  SWAPZ_BENCH_BATCHES="4 16 64 256 512 1024" \
  bash tests/runtime/streaming-benchmark.sh
```

**Do not run this full matrix as the first kernel smoke test.** First use a
single short case (`SWAPZ_BENCH_STRATEGIES=immediate`,
`SWAPZ_BENCH_BATCHES=4`, `SWAPZ_BENCH_RUNTIME=1`) and verify:

1. the kernel NBD device is 256 MiB and no other consumer is attached;
2. the model's server starts and exits normally;
3. the test's DM mapping is removed before NBD disconnect;
4. reads exactly match written data, including at 1 MiB request boundaries;
5. the lower `/sys/class/block/nbdN/stat` reports plausible read/write I/Os;
6. the model can accept a **single 1 MiB lower request** (not just 1 MiB
   user I/O silently split into smaller requests);
7. measured raw-NBD drain is reasonably close to the configured 20 MiB/s,
   within a documented tolerance;
8. no DM/NBD/fio task remains and no new kernel warning/hang occurs.

The benchmark script never chooses an NBD device automatically. Its Python
server also checks the explicit device path and existing holders/mounts/swaps.
A device node must be a real (not symlinked) block node whose major/minor
number matches /sys/class/block/nbdN/dev. The server rechecks the opened
file descriptor before the first NBD ioctl to reject a path-replacement race.
The rootless selftest includes spoofed-device identity, full-size NBD
socket readback, and timeout-after-partial-send regressions.
If the normal DM removal fails, the cleanup helper retains the NBD session
and diagnostic files rather than disconnecting it under a live mapping.
The NBD server now records disconnect/clear-socket ioctl failures and does not
report successful exit until its kernel worker has stopped and cleanup
completed. Modeled transfer waits are interrupted by a stop event; an unusual
bandwidth/latency setting cannot silently model a request longer than the
NBD timeout safety margin. If `NBD_DO_IT` remains stuck after the bounded
five-second join, the server **reports a shutdown error and continues holding
its descriptors until the worker exits**. This is deliberately not a bounded
process exit: preserving the session is safer than closing a potentially
DM-backed live kernel connection. Investigate holders/task state; do not
SIGKILL/force-detach a live DM-backed device as an automatic workaround.
Never force-remove mappings or reboot without authorization.

## Experimental validity rules

- Only report a 20 MiB/s plateau after confirming the backend really emitted
  512 KiB and 1 MiB lower requests and its measured service rate is calibrated.
- Report upper-completion and end-to-end drain throughput separately.
- Include concurrent swap-in p99, lower I/O count/sectors, GC, and RAM cost.
- Compare against null_blk unthrottled overhead and safe <=256 KiB throttled
  controls; the two controls answer different questions.
- If the NBD kernel driver splits 1 MiB requests, measure the actual maximum
  request size and declare the large-request plateau unresolved.
- Reject any new correctness/forward-progress failure before benchmarking.
- Do not change the validated swapz kernel to accommodate a synthetic backend.
- This optional backend is NOT production software, a durability test, or
  permission to use physical media.
