# V2.2 request-size plateau model

Date: 2026-10-07

This is an analytical sizing sweep, not a hardware benchmark.

Model:

```text
request_time = fixed_command_latency + request_bytes / media_bandwidth
physical_throughput = request_bytes / request_time
```

The model exists only to determine how far the real `null_blk`/physical sweep must go.
It does not choose the final batch size.

For a nominal 20 MiB/s device:

| Fixed command latency | 32 KiB | 64 KiB | 128 KiB | 256 KiB | 512 KiB | 1 MiB | first >=97% of media ceiling |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.25 ms | 17.24 | 18.52 | 19.23 | 19.61 | 19.80 | 19.90 | 256 KiB |
| 0.50 ms | 15.15 | 17.24 | 18.52 | 19.23 | 19.61 | 19.80 | 512 KiB |
| 1.00 ms | 12.20 | 15.15 | 17.24 | 18.52 | 19.23 | 19.61 | 1 MiB |
| 2.00 ms | 8.77 | 12.20 | 15.15 | 17.24 | 18.52 | 19.23 | >1 MiB for a strict 97% ceiling criterion |

For the 2 ms case, the incremental gain from 1 MiB to 2 MiB is only about 2%, so a
latency-aware plateau rule may still prefer 1 MiB even though the strict 97% ceiling point
occurs at 2 MiB.

Projected logical throughput if compression/packing reduces physical bytes:

| Physical throughput | 2x reduction | 3x reduction | 4x reduction |
|---:|---:|---:|---:|
| 15 MiB/s | 30 | 45 | 60 |
| 17.5 MiB/s | 35 | 52.5 | 70 |
| 19 MiB/s | 38 | 57 | 76 |
| 20 MiB/s | 40 | 60 | 80 |

Therefore the 60-80 MiB/s logical stretch target on ~20 MiB/s media requires both:

1. physical request sizing/pipelining close enough to the device's sequential plateau; and
2. approximately 3-4x effective physical-byte reduction for the tested memory mix.

The real V2.2 benchmark sweeps:

```text
4, 8, 16, 32, 64, 128, 256, 512, 1024 KiB
```

for the streaming policies that support batching. It chooses the smallest request size at
>=97% of the best measured physical drain throughput, then applies a concurrent swap-in
latency guard. The batch ceiling is therefore a measured property of the device/workload,
not a design constant.

Reproduce:

```bash
python3 bench/request-plateau.py --bandwidth 20
sudo bash tests/runtime/streaming-benchmark.sh
```
