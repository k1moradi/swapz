## Concrete incompatibilities and first decision

1. **STORED is not typed capture.** zswap_store_page stages actual original folio bytes before compression and finish_input uses entry->original_cookie after actual XArray insertion. swapz_mm_capture in compressor only mints cookie on compatible codec/provider/route; original_cookie is not general ordinary store identity. Byte bridge capture_input (303) requires SWAPZ_OBS_TYPED_WRITE; bind_input consumes committed slot/store bank through typed collector; accept_operation (344) explicitly rejects nonzero slot/store/area_epoch/swap_type/generation on ordinary ACCEPT. terminal_ready (472) requires no staged/committed inputs, and no ordinary retirement hook consumes the committed bank. Cannot reinterpret ordinary accepts as STORED provenance or clear banks to make cleanup pass.
2. **Real native eviction has different timing.** Pinned Linux shrink_memcg_cb takes swpentry under LRU lock, drops it and calls zswap_writeback_entry. Only after new locked swapcache folio and exact XArray pointer match is entry safe to dereference; decompress must succeed. Existing preerase is typed carrier reserve/seal plus original stream capture; ordinary Phase A needs no provider cap, lease, codec/length selection or typed candidate. Native xa_erase and zswap_entry_free happen BEFORE __swap_writeout and swap_write_submit; return 0 and ZSWPWB are not lower/upper ACK. Two actual facts (erase/free and successful original completion) joined by value identity are needed for evict_retired after write_upper. Do not delay native free to fit schema.
3. **Durability conflict is concrete.** dm_swapz_trial_observation_origin rejects REQ_PREFLUSH|REQ_FUA|REQ_NOWAIT|REQ_POLLED|REQ_ATOMIC (and typed carrier). Yet swapz_raw_write's old ordinary witness requires REQ_FUA; swapz_lower_write requires prepublication_fua. Base swap_bdev_submit_write constructs REQ_OP_WRITE|REQ_SWAP. Thus old ordinary RAW/FUA success witness cannot establish the required natural ordinary durable commit. Ordinary packed/zero/bulk are explicitly invalidated by swapz_accept_write; lower helper marks submit before common lower validation/fault injection. No extra flush, FUA, forced RAW, verify-read, or changed routing to manufacture an event. A1 must decide whether approved existing backing/ordinary durability proof (including required prepublication fence or independently verified no volatile-cache semantics) is actually available; if not, no qualifying v2 write_commit, UNKNOWN. If an ordinary write ACK cannot satisfy frozen durable semantics, review contract/schema explicitly rather than silently weaken. A single logical 4096-byte commit is not a claim that physical RAW_4096 was written.
4. **Read path absent.** Base swap_read_folio first tries zeromap and zswap_load, only -ENOENT proceeds to swap_add_folio READ. Target plain accept (16989) marks READ selected, defers ordered classification; swapz_read (12156+) chooses typed map vs invalid/RAW vs ordinary packed decoding. At 12288 it explicitly invalidates an ordinary READ; swapz_scope_observe_read_pin/copy is typed-only. Old recorder allowed-fields and collector enums do not represent ordinary STORED/readback chain. No alias to SWAPZ_OBS_TYPED_READ or ORACLE. Existing consumer requires three full pages (write_bio, read_upper, read_user) independently equal plan, not hashes or decode scratch.
5. **Exact lower and final completion boundaries.** Actual swapz_lower calls dm_io with one region and observes aggregate return/error bitmap. Pinned upstream dm-io.c do_region may loop creating multiple BIOs, endio collects status, dec_count closes aggregate. One dm_io invocation is not proof of one child. The current v2 allows one lower token and one pair of actual lower byte counts per operation; do not double-count a shared packed extent or treat a sum as an individual page request. Define lower event at one attributable submitted child with exact pre-submit saved length and completion; below that boundary request-level split/merge remains unproved, not physical request-count credit. If actual child split, merged/multiregion/multiple lower requests, cache hit, GC/verify read, async shared range, short/ambiguous completion or split/requeue core, reject capture without changing native I/O. If useful ordinary shapes routinely cannot fit v2, A1 must review a later version; no force-unmerge or extra I/O for observation.
6. **Independent user witness and strict serial scope.** v2 requires full independently committed expected bytes, independently retained late STORED witness and actual user readback; native target cannot supply all three. Plan logical IDs are fixed pre-run; actual mapper data-sector / 8 and selected area slot must match the precommitted identity mapping. A userspace array index is not a known swap slot, allocation order is not proof. If mapping cannot be established independently without changing allocator or plan after seeing capture, UNKNOWN. Generation is a nonzero frozen per-STORED incarnation repeated in all rows; existing target map generation is separate and must be saved/checked at actual publish and read (never predict a commit from next generation). Define distinct nonreused store ordinal and entry cookie, checked nonwrapping generation; do not alias pointer values or invent generation based on target guess. Actual IDs minted by owners, not manifest producer. No same-round A2 implementation needed. v2 serial groups (stored through read_user) prohibit interleaving; do not reorder real timestamps or buffer to fake order. A later independently approved one-page case is the smallest candidate; for interleaved/multiple-page natural workloads report UNKNOWN unless reviewed schema supports them. No pressure tuning or forced reclaim to produce a particular sequence.
