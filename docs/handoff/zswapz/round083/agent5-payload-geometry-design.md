## 2. Exact geometry (arithmetic, not performance measurements)

For extent E in {4096,8192,16384}, payload-only, no per-record padding, n=min(64,floor(E/L)), pad=E-nL, physical bytes/record=E/n. Table entries n / pad bytes / payload occupancy%; 4096 is **not** original compressed and is shown as ordinary dedicated RAW only. Homogeneous full extents; actual planner may choose smaller extents, not fill larger ones. Original lengths1,3568,3569,4095 represent geometry alone, not a guarantee of valid encoded bitstreams.

| 1 | 64 / 4032 / 1.5625% | 64 / 8128 / 0.7813% | 64 / 16320 / 0.3906% |
| 3568 | 1 / 528 / 87.1094% | 2 / 1056 / 87.1094% | 4 / 2112 / 87.1094% |

| 4096 | 1 / 0 / 100.0000% | not allowed RAW packing | not allowed RAW packing |

Dedicated4KiB: padding 4095/528/527/1 bytes for L=1/3568/3569/4095, one full block and 8 sectors per original. For L=4096 RAW pad0. Large homogeneous lengths3568..4095 allocate exactly one block per logical page for all classes; 4095 being 99.98% payload occupancy is NOT capacity savings. 1-byte homogeneous groups of64 save 63/62/60 blocks vs64 RAW for 4/8/16KiB respectively (64 cap, so 65th needs another extent; larger is wasteful). For general n, saving=4096*n-E, and record count cliff n changes at floor(E/k) versus floor(E/k)+1, k<=64 (e.g. 2048->2049 in 4KiB; 2730->2731 for three in8KiB; 3276->3277 for five in16KiB; 64->65 bytes for64 in4KiB). Large threshold3277 still mathematically valid with new cap4095: at most1/2/4 such records per1/2/4 blocks, even with smaller siblings.

Adversarial ordered examples:
- [4095,1] or [3569,527] fit exactly 4KiB, 2 records, save4096; [3568,529] or [4095,2] total4097 needs >=8KiB, no block saving versus 2 dedicated. [4095,4095,1,1] fills8KiB, saves8KiB vs four dedicated; descending packing offsets4097,2,1,0, second record crosses a block. [3277]*5 =16385 cannot fit16KiB, requires at least5 blocks; a single 16KiB plus4KiB allocation has pad4095. 64 tiny records + a long record can cross record-count cliff even if byte fit would allow it; do not silently exceed64. Reordering only when existing ordered owner proves independent logicals and no durability/overwrite dependencies; initial use ordered planner.
- For contiguous descending offsets, cursor=E; if 0<L<=cap and L<=cursor, offset=cursor-L, cursor=offset. Zero [0,cursor) at seal (dedicated offset0 and suffix zero may be used for A, but uniform descending offset for B). Prove descriptor intervals disjoint and gap-free and no duplicate logical within batch, exact CRC over bytes. u16 offsets/length safe (max E=16384, L<=4095), do subtract-before-add with widened u32 for bounds; no overflow sector arithmetic (existing checked sector_t), no alignment assumption for compressed bytes; 1/2/4-block allocation cannot cross 256-block segment, use existing allocation alignment policy and bad-page translation. Legacy serialized header+descriptor would consume 32 bytes even for a singleton; 4095 cannot fit that format, which is not production.
- Lower WRITE 8/16/32 sectors per extent; cold selective READ ceil crossing formula ((offset+L-1)>>12)-(offset>>12)+1 gives1 or2 blocks for 1..4095, one block for aligned RAW/dedicated, 8 or16 sectors, never need full16KiB for single record. E.g. 4095+1 4KiB both read one block; 4095+4095 8KiB reads1 and2. Full extent scan during GC can amortize reads, not assumed. Read amplification per requested 4096 decoded page 1x or2x (relative to compressed bytes =4096/L or8192/L); cache hits not guaranteed. Count lower actual sectors separately from logical bytes and requests. Use existing max-read-blocks constraint, choose no crossing if policy demands1, no fixed time-based pack delay.

## 4. Storage consumer transaction and failure ownership

Abstract API (not Agent11 dependency):
  try_reserve(target_incarnation, logical, source_generation, length, codec_profile) -> token or DECLINED
  copy_and_seal(token, immutable_bytes, authoritative_full_page_sha, compressed_crc, provenance) -> owned token or DECLINED
  enqueue_owned(token, original_page_failure_owner, real_upper_completion_owner) -> ordered operation
  abort_unaccepted(token) -> once-only resource return

Reserve nonblocking try/credits, no disk I/O or wait at producer. Check exact selected target/session and logical slot, nonzero length<=4095 for qualified typed route (today gate OFF and conservative cap3568), no overflow, codec/version/dictionary whitelist, available independent decoder and sidecar/byte/GC/block credits. Copy before source erasure into preallocated private 4096 buffer; validate CRC and independently obtained full-page SHA (decode into private scratch to check exact4096 before accepting; producer must not be forced to sleep, verification may run later only with valid full-page fallback owner). No source handle retained. The owned immutable token and real original-page failure owner must be established before source loss. Lower image prepared under ordered owner only; repeat tuple/slot/DM generation and seal checks, use existing swapz_stage/stage_batch_unique real allocator, no new allocator, guard segment/record count/duplicate/ranges. Bind descriptor and zero pad, CRC exact before submission, immutable lower buffer until actual completion. No accepted original bytes enter swapz_compress_page/predictor.

State: FREE -> RESERVED -> SEALED (copy immutable) -> LOWER_SUBMITTED -> DURABLE -> PUBLISHED -> ACK_ELECTED -> ACK_DISPATCHED; errors after submit -> QUARANTINED and abort pending map; after publication old map becomes RETIRED until last pin. Only actual lower callbacks validate exact byte/block completion. Require real successful lower WRITE plus FUA or successful accounted flush BEFORE publication for original typed imports, independent of ordinary optional prepublication_fua. Reuse actual lower submit and swapz_issue_flush; do not synthesize flush_completed or ACK count. Original write obeys existing preflush/FUA and ordered predecessor; no publish on partial, failed or uncertain lower. Durability here same-boot block semantics, not a reboot recovery claim. Validate full prospective authority/deltas/hash before lower and revalidate before publish; all post-preflight edits non-failing. If stale during I/O, never install stale map. Keep old valid mapping until replacement durable; old physical liveness decremented for current map, pinned retired physical extent protected separately. Publish map+sidecar+segment list/cost+liveness together under ordered owner, invalidate affected caches, release-store or owner lock. Exactly one completion owner atomically elects result, dispatches real completion outside locks. Do not invent ack_count=1 to placate dormant decoder: production read authority is durable published generation with ordered write predecessor; hold dependent dispatch until completion elected/dispatched as appropriate, actual completion counter only from real owner. No double endio even if lower/flush failure and teardown race.

Read: ordered map selection/tuple validation; pin stable descriptor/ticket + physical extent and acquire decoder lease before releasing owner; use checked existing lower sector translation and selective range, verify exact lower result then CRC and original codec/version, decode exact4096 into disjoint scratch, compare original SHA; copy to real upper only on success, one completion, release decoder/read/physical refs in reverse. Need an internal decoder adapter that checks selected slice length separately from actual whole-sector read length; current helper demands compressed_length at157, not physical byte count. No fabricated physical receipt. Initial original route bypasses ordinary caches and concurrent read slots; use dedicated bounded read owner. Before enabling cache, key includes start/extent sequence/session/mapgen/type; never route a retired old-generation read through current-map helper. Read linearizes at ordered snapshot.
