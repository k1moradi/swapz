## Real original SOURCE conditions: PTE direct counted owner versus locked swapcache owner

1. **Genuine `swap_dup_entry_direct` is not a constructor from any copied slot.** Original `mm/swapfile.c::swap_dup_entry_direct(swp_entry_t)` requires the caller **already to own** a direct counted slot (e.g. a swap PTE protected by its page-table lock/PTL), with **swap count >= 1** and no race with release/replacement of that owner. Its `swap_entry_swapped` only briefly locks the cluster to read a count, unlocks, then `swap_dup_entries_cluster` reacquires its own lock: a concurrent slot-recycle/ABA can change the owner between those independent checks unless the caller's preexisting direct ownership prevents it. The helper cannot legitimize a stale `swp_entry_t`, numeric epoch or old STORED SHA/CRC.

2. **The original kernel does have a different *conditional candidate*: `folio_dup_swap`.** In `mm/swapfile.c::folio_dup_swap(folio, page)`, the caller **must already hold a locked, current swapcache folio**, and the owner must not race a direct `swap_put_entries_direct` count release during the operation. The swapcache pin may legitimately hold a slot with count **zero**; `folio_dup_swap` calls `swap_dup_entries_cluster` and can mint a counted reference from that living folio, while `swap_dup_entry_direct` requires an already counted direct PTE owner. The kernel's private `__swap_cluster_dup_entry` requires the cluster lock; permits existing counted or swapcache folio slot, checks bad/empty slot, increments the count or uses its atomic extended table; `swap_dup_entries_cluster` performs `-ENOMEM` extended allocation outside the spinlock, relocks/restarts, and rolls back partially acquired counts on failure. A future retained ref would need one uniquely owned, balanced count release via an original valid API such as `swap_put_entries_direct`, including all failures, aborts, duplicate callbacks and swapoff. **That acquisition/transfer/release is NOT implemented in the original zswap writer** and must not be silently added as a source positive.

3. **Earliest potential source window is narrow and not an authorization.** Original `mm/swap_state.c::__swap_cache_alloc` checks nonzero count and absence of conflicting folio under a cluster spinlock, unlocks for allocating the new folio, re-locks, validates again, and installs a **locked swapcache folio** with `folio->swap`. Original `mm/zswap.c::zswap_writeback_entry` first obtains a scoped swap **AREA** users ref via `get_swap_device`, allocates that folio, **puts area ref**, then under the locked folio verifies `entry == xa_load(tree, offset)`, decompresses, erases/frees original STORED zpool entry, drops its extra folio ref, and invokes `__swap_writeout`/`swap_write_submit`. The actual locked-folio-plus-current-xarray window after validation and before `__swap_writeout` unlocks the folio is the **first plausible** place to examine a new counted ref from `folio_dup_swap` with a separate explicit owner. It has NOT been acquired, callback-transfer-reviewed or paired with complete unwind, source bdev/nonlinear sector, and live current DM target/GC/dtr lease. The existing original path does not call either `folio_dup_swap` or `swap_dup_entry_direct` or create an external counted owner.

4. **Original folio/area/BIO are distinct owners.** `mm/page_io.c::__swap_writeout` calls `folio_start_writeback`, unlocks the folio, submits a true `REQ_SWAP` original full **uncompressed** 4096 upper BIO on `ctx->sis->bdev` and `swap_folio_sector` physical 512-byte potentially NONLINEAR backing sector. `end_swap_bio_write` calls `bio_uninit` then `swap_write_end`/`folio_end_writeback`. `mm/swap_state.c::swap_writeback_dropbehind_folio` deliberately checks a potentially already-removed swapcache folio and may return it to LRU on race. `__swap_cache_do_del_folio` can free a slot when counts reach zero and writeback protection ends. This protects **original internal** writeback but cannot be treated as an external lease for independent lower-I/O completion, clone/reissue/ABA, swapped-off area reuse, GC or table teardown. `swap_put_entries_direct` acquires an area users ref to put a genuinely preexisting counted slot; it is not evidence such a ref was acquired.
