## True original C ownership boundaries

- Original `mm/swapfile.c::get_swap_device` calls `percpu_ref_tryget_live(&si->users)` through `get_swap_device_info`, checks only typed entry and `offset < si->max`, and returns an **AREA-lifetime** `swap_info_struct`. `put_swap_device` in original `include/linux/swap.h` puts `si->users`. It neither locks the per-slot swap-table entry nor increments its swap count. Original `swapoff` kills area users ref, synchronizes RCU, and waits for completion. A scope is valid only before its matching put.
- The actual original allocated-slot owner is the swap-table count or swapcache-folio presence under its cluster lock, not an independently transferrable scalar epoch. `__swap_cluster_free_entries` resets an exhausted entry to `null_to_swp_tb()`; `swap_range_free` invokes `zswap_invalidate` and then returns that slot to usage accounting. Subsequent assignment can reuse the same type+offset; a copied `swp_entry_t` cannot tell which allocation incarnation occupies it.
- `swap_dup_entry_direct` does increment a **counted** direct slot reference via `swap_dup_entries_cluster`, but its true original contract requires the caller already possess a stable direct counted swap entry protected by its reference-owner lock (e.g., page-table PTL), with count >= 1. The zswap observer's copied typed slot and former xarray equality are **not** that direct counted reference. Calling this helper after release would risk pinning a different occupant; it is not an observational permission.
- Original `mm/zswap.c::zswap_writeback_entry` takes a short area ref, calls `__swap_cache_alloc_folio`, puts area users ref, validates the **locked folio plus current `entry == xa_load(tree, offset)`**, decompresses, erases the xarray entry, frees the original zpool/store owner, and then drops its extra folio reference and enters `__swap_writeout`/`swap_write_submit`. The original swapcache folio and PG_writeback provide their own internal lifetime until original completion; this **does not** hand an independently counted source slot-incarnation ref to another async Device Mapper lower-I/O owner. If `__swap_cache_alloc_folio` fails, original returns error without source transfer; if matching/decompression fails, the original `err:` path removes, unlocks and puts its folio. No borrowed zswap entry survives its `zswap_entry_free`.
- Original `mm/swapfile.c::swap_folio_sector` uses the swap extent mapping and `se->start_block + (offset - se->start_page)`, then shifts to physical **512-byte** backing sectors. This can be nonlinear for a swapfile and is not the offset of an arbitrary **current target-relative 8-sector** DM table range. `mm/page_io.c::swap_bdev_submit_write` initializes genuine `REQ_OP_WRITE | REQ_SWAP` BIO on original `ctx->sis->bdev`, with `swap_folio_sector`, and sends synchronously through `submit_bio_wait` or asynchronously with `end_swap_bio_write`; the latter calls `bio_uninit` and `swap_write_end`, which finishes `folio_end_writeback`. `block/bio.c::__bio_clone` clones iter/bvec view and `bio_endio` dispatches callback but neither mints nor transfers a swap-slot allocation ref.
