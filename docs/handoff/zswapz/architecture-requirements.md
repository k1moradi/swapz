# zswap + swapz — owner-approved cooperative compressed-tier requirements

**Approved November 16, 2026.** This is the normative architectural target in the `docs/handoff/zswapz` engineering ledger. It records requirements and *does not mean the compressed transport is implemented, loaded, authorized or enabled*. Apply [AGENT_CONTEXT](../../AGENT_CONTEXT.md), [VISION](../../VISION.md), [technical context](../../context.md) and [testing standards](../../testing_standards.md) at all times. No current round may silently change active production, kernel reclaim, on-media format or physical admission.

## 1. Exact layering and ordinary SWAPSPACE2 invariant

- **zswap:** bounded, *configurable* small share of RAM (product aim: a few percent; choose any exact percentage only after benchmark and memory-pressure review), compresses/reuses useful swap pages in RAM. Linux MM/zswap continues deciding store eligibility and eviction under genuine pressure; **no competing swapz RAM-reclaim/pressure controller** and no forced eviction merely to fill disk.
- **swapz:** the Linux **disk-backed swap tier**, with existing staging/packing/swap-in and fast compressor; no new disk partition format and no second autonomous reclaim policy. Each page's destination path is selected on authenticated provenance and representation, not PID, folio bit, timing, or compressor name guessed from a BIO.
- **Physical backing:** exclusively the *existing valid Linux `SWAPSPACE2` swap partition*, unchanged first **4096-byte** header, UUID, signature, partition table and ordinary swap ownership. After the owner-authorized `swapoff`/exact-exclusive admission, only post-header data-area blocks may be used. **Never** `mkswap` the physical partition; only the newly created, independently authorized virtual Device Mapper swap device may be `mkswap`'ed. Preserve normal transition back to ordinary swap, original header and cleanup/restore rules.
- **Production representation on backing partition:** 4/8/16 KiB swapz physical extents remain **payload bytes plus deterministic zero padding only**, not SWZ headers, magic, sidecars, codec IDs, CRC fields or record/GC tables on media. Bounded volatile **RAM** stores per-logical-swap-page representation, codec/version, exact payload byte count, generation/epoch, offset/length, immutable snapshot lifetime and GC/integrity/allocator/segment authority. RAM mapping loss is not recoverable from lower payloads; **no hibernation/crash-resume assertion**.
- Linux swap slots/logical pages are **4096 original bytes**, independent of their backing payload length; no upper READ/WRITE user-visible byte-count change. Maintain page-zero protection across WRITE/DISCARD/GC. Compression, checksum and layout must remain bounded under the existing memory and device capacity limits.

## 2. Decision table: who compresses and who decompresses?

| Event | Authorized storage representation | Required action / result |
| --- | --- | --- |
| Initial swapout accepted into zswap RAM | zswap-owned compressed RAM entry, no disk record yet | zswap retains and manages RAM; no swapz disk write or compression |
| Subsequent swap-in while entry remains in zswap | zswap-owned RAM entry | **zswap decompresses** and returns original 4096 bytes; swapz need not read disk |
| Genuine previously stored entry later selected by zswap for eviction, supported verified codec/ABI/ownership | **proposed distinct `ZSWAP_COMPRESSED_LZ4_V1` RAM descriptor** | Transfer the *actual existing compressed bytes* without decompress→recompress, reuse safe RAW path *staging/copy/lower-I/O machinery only*, store compressed payload with separately tagged identity/generation/integrity; on future disk READ **swapz decompresses** with compatible LZ4 decoder and returns original 4096 bytes |
| Genuine stored entry but unsupported codec, oversized/invalid payload, no safe immutable snapshot or no authenticated transport | existing standard original-page path | zswap decompresses to original 4096 bytes; submit ordinary swap WRITE; swapz may run its fast codec and existing RAW fallback; no silent data loss or forged origin |
| Ordinary direct swapout (zswap disabled, rejected, or not retained) | existing `SWAPZ_COMPRESSED` (LZ4 / delta64 / SHUF8 + LZ4) or `RAW_4096` | swapz uses existing fast compressor/packing with original-page RAW fallback, then matching swapz READ decoder returns 4096 original bytes |
| Zero, cancelled, overwritten, slot reused, failed I/O or DISCARD | existing zero/invalid/GC/error semantics | Preserve existing correctness/upper error/ownership; no stale generation revived by speculative compressed handoff |

**Critical distinction:** today's **`RAW` is the full original UNCOMPRESSED 4096-byte page.** Reuse existing RAW transaction/lower-page infrastructure if safe, but a new compressed payload **must never be labeled or decoded as ordinary RAW**. Example `ZSWAP_COMPRESSED_LZ4_V1` names above are proposed conceptual tags, **not reserved kernel ABI values or a format already implemented**. An existing zswap-origin BIO tag currently signals provenance of an **already decompressed 4096-byte ordinary swap WRITE**, not compressed contents. A normal REQ_SWAP/WRITE BIO cannot silently carry a different variable-length buffer.

## 3. Versioned authenticated representation / memory ownership (v1 design gate)

- First MVP supports **zswap LZ4 only** after proving the actual zswap entry's configured codec *at store time*. An entry can outlive a compressor configuration change. zswap ZSTD, unknown codec/dictionary, codec unavailable in DM kernel, wrong length, page-size or provenance -> original-page fallback. No direct ZSTD or arbitrary LZ4 format assumptions.
- A future producer/consumer ABI must preserve **actual zswap compressed bytes**, exact length, *original decoded_length=4096*, codec ID/version/optional dictionary identity, logical swap slot and generation/epoch, source stored-entry identity, full original-page integrity token, compressed-payload CRC32C, and one unambiguous **ownership/lifetime/teardown** state. Explicitly distinguish *stored entry eviction*, initial zswap rejection, ordinary swapout and synthetic test tags.
- The current **compile-disabled** research producer computes **CRC32**, while proposed/consumer expectations include **CRC32C** and an independent original-plaintext digest; **CRC32 != CRC32C**. Do not transfer or decode until the protocols agree on exact algorithm and data bytes. For qualification, independently known original 4096-byte SHA256 (ideally captured while plaintext was available at zswap store, accounting for RAM/CPU budget) and exact full-page memcmp are required; do not trust a checksum over only compressed bytes to prove plaintext correctness.
- The producer must authenticate previously admitted/retained compressed entry's xarray/swapcache identity and generation with appropriate locking, ensure immutable payload copy or proven safe ref before zpool storage reuse, and publish one consumed handoff only after successful capture. A pointer/borrowed scatterlist that expires before lower completion cannot be a durable payload.
- Admission must remain bounded in bytes, descriptors and outstanding pages; preserve the `SWAPZ_MAX_COMPRESSED=3568` current production bound for candidate records unless a separate proven budget/layout change is approved; fallback for too-large data. No unbounded `kmalloc`, per-page hash work in hot loop without budgets, unbounded retry, synthetic upper success, or post-ACK mutable source pointer.
- On swapz, one authenticated **logical swap page+generation** owns one immutable *representation* (`RAW_4096`, existing swapz codecs, or future zswap LZ4). Physical extents may mix records **only** when the per-record RAM decoder identity is exact. On overwrite, reissue, late completions, GC relocation, DISCARD, swapoff or retry, no stale codec or generation can be exposed, double-freed or silently converted.
- Preserve **write completion authority**: lower successful durable foreground WRITE + authoritative mapping publication precedes exactly-once upper ACK; no early success or bypass of FUA/PREFLUSH/GC fences. READ validates owned current generation, correct compressed length/CRC32C, **decompresses to exactly 4096** in properly owned output, checks original-page integrity, and only then returns success. Decode/read/CRC failures propagate original errors; never expose partially decoded bytes as success.

## 4. Staged engineering and proof requirements

1. Freeze and independently test the **same source-level v1 wire/sidecar representation contract** with producer/consumer *negative* source tests; do not rely on current ordinary BIO `bi_swap_origin` scalar as proof compressed bytes exist. Develop real Linux MM/zswap to DM payload handoff ownership that survives clone/split/reissue. Publish prototypes independently on one `main`, but **compile- and runtime-disabled** by default until loaded acceptance.
2. Source-bound compiler tests cover good LZ4, compressed bit flips, incorrect CRC32/CRC32C mix, wrong original 4096 SHA256/bytes, length 0/>max, unsupported codec, duplicate submit/finish, ABA slot reuse, late callback, mixed-origin BIO, wrong transfer size, overlapping/GC generation and short or failing lower READ, including actual production decoder code rather than hand-waved mock parsing.
3. Preserve **actual pinned modified Linux y/n KUnit 5/5** and matched DM build identity. Rootless/source/KUnit/mock/offline comparisons are useful gates but *not* evidence of genuine compressed stored-entry eviction to loaded DM or original swap-in.
4. **Phase A qualification** requires independently authenticated **booted exact modified Linux**, truly loaded **matching** `dm-swapz.ko`, specifically owned ephemeral **RAM-only** target and authorized bounded actual zswap store/eviction, genuine compressed byte handoff→committed DM WRITE/upper success→kernel READ returning byte-exact original 4096 page, with safe teardown; only after acceptance may a separately authorized protected SWAPSPACE2 partition trial be considered. Source-built and self-attested status evidence alone always fails.
5. Performance gate after correctness: compare old decompress→swapz recompress vs new direct compressed LZ4 with same-pressure content, RAM pool budget, disk bytes/requests, useful WRITE latency, READ decode cost, CPU and GC/swapoff, including ordinary pages on swapz fast codec. Do not choose a competing reclaim scheduler or present speedups without actual controlled results.
