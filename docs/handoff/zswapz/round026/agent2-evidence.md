## GO/NO-GO: original source does NOT mint a reuse-safe slot allocation epoch

**NO_GO for direct compressed zswap→swapz handoff.** This is an original-kernel API/ownership blocker, not an omitted clock or simple allocation of a `u64` in an entry:

- Real `mm/swapfile.c:__swap_cluster_alloc_entries(struct swap_info_struct *si, struct swap_cluster_info *ci, struct folio *folio, unsigned int ci_off)` holds `ci->lock` (`lockdep_assert_held`), and checks `SWP_WRITEOK`. For an original folio, it calls `__swap_cache_add_folio(ci, folio, swp_entry(si->type, ci_off + cluster_offset(si, ci)))` and `swap_range_alloc(si, nr_pages)`; hibernation uses a count-only shadow placeholder. The allocator scans under that cluster lock; `alloc_swap_scan_cluster()` drops the lock only after the allocation decision. This is the **source-owned mint point** at which an epoch would have to be atomically committed, per all 1<<folio_order pages, before the folio is exposed.
- Under the SAME cluster lock, original `mm/swapfile.c:__swap_cluster_free_entries()` clears the slot table with `__swap_table_set(ci, ci_off, null_to_swp_tb())` and zero flags, then `swap_range_free(si, ci_head+ci_start, nr_pages)`; `swap_range_free()` synchronously calls `zswap_invalidate(si->type, offset, nr_entries)`. Different call sites include `swap_put_entries_cluster`, `swap_free_hibernation_slot`, swapcache release and reclaim. The old `swp_entry_t` value and swap table bits become available for SAME-slot reuse; freeing, hibernation, large orders, failed allocations and concurrent old callbacks can all revisit identical raw values.
- `struct swap_cluster_info` owns spinlock, reference-count/folio table and cluster allocation state, but no persistent per-allocation `u64` epoch; `struct swap_info_struct` owns `users` (percpu_ref) and swap type/cluster arrays, again no epoch map. Its `swap_info[type]` is reused on swapon; `alloc_swap_info()` explicitly does NOT zero the existing type when reusing it, and `free_swap_cluster_info()` destroys the original tables during swapoff after waiting for allocation quiescence. `get_swap_device(swp_entry_t)` pins the device lifetime via `get_swap_device_info()` / `percpu_ref`, **not the slot incarnation**. Neither `__swap_table_get`, `swp_tb_is_folio`, `swp_tb_get_count`, `ci->count`, source slot integer, folio address, pool handle, LRU order nor `xa_load` contains an allocation epoch. Observing a valid current entry under `ci->lock` never proves it is the same allocation as an earlier STORE after unlock.
- Source `mm/zswap.c:zswap_store_page()` sees an independently locked original 4096 plaintext folio and per-page `folio_swap_entry()`; Round025 GCC CI-only `sha256(original_bytes,4096)` witness is valid **as a temporary digest feasibility check**, not retained production proof. Original zswap STORE/WRITEBACK, invalidation and swapoff store no allocator-issued epoch or protected original SHA bound to that epoch. A zswap pointer check at eviction can prevent one stale use, but cannot substitute for a refcounted, generation-bound compressed BIO owner crossing retries and DM. Original ordinary decompression → UNCOMPRESSED 4096 `REQ_SWAP` WRITE remains unchanged.

**Minimal safe design to unlock a later GO (not implemented/live this round):** Mint a strictly monotonically increasing nonzero `u64` value from an actual MM allocator-owned issuer at the first successful `__swap_cluster_alloc_entries()` per slot, while holding `ci->lock`. Before any allocation state is published, reserve capacity for a bounded per-slot epoch lookup (either dense `si->max * sizeof(u64)` budget vetted at swapon or explicit bounded sparse issuer table) and make failures abort the swap allocation rather than partially reuse. Mint for every allocated slot including large folios and hibernation. The issuer must NOT reset for reused `swap_info[type]`/swapoff+swapon, and zero/exhaustion/`U64_MAX` must be permanently fail-closed, never wrap. Store a lookup binding indexed by actual swap type/slot that can be read while source folio lock and cluster lock stabilize the same allocation, then capture it into the new zswap entry along with its independently hashed original 4096. On last-ref release, invalidate/retire the generation under `ci->lock` before table NULL/free and before any slot reuse; reject stale callbacks/cancellation. Preserve old generation records until all independently owned BIO/DM references drain, with RCU/refcount and explicit lock hierarchy; never hold `ci->lock` across allocation, SHA, BIO submission or callbacks. Pool rotation and zswap entry replacement require matching original source epoch and pool lifetime, distinct from DM logical generation and GC relocation epoch. Budget, wrap exhaustion, swapon fallback and copy ownership must be verified by truly compiled allocator hooks and loaded/verified swap-in before GO; adding `atomic64_inc` to a standalone helper is NOT equivalent.
