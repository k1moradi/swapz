## Source-backed lifetime repair and native isolation

The old fixture's decoder-retire cleanup held a risk: it did not drop an unexpectedly acquired `late` lease and used unbounded `wait_for_completion(&closer.returned)`; the closer waits for active decoder-reader count to drain and can deadlock if the test retains a pin. The new fixture releases `late` and the original `lease` before any closer join. It preserves the existing 1500ms bound, with heap-stable owner/closer storage so a failed completion can fail the test and quarantine still-borrowed test-only storage rather than blocking indefinitely or freeing a borrowed stack (UAF). A no-worker path checks active-reader zero before a synchronous drain. This is a source-correctness improvement and a concrete risk mitigation, **not yet evidence that the Round079 third-case runtime cause was solely this cleanup**.

A new fail-only 20-second phase watchdog prints exact stage and reader count if the genuine original KUnit stalls, without raising the overall 120-second timeout. The workflow preserves original native `test.log` on failure, runs stale CRC/SHA/codec and decoder-retirement cases independently with shorter 40-second per-boot limits using one shared original UML build directory, and then requires the complete actual 4/4 native JSON **AND** KTAP. Original LZ4 and LZO1X GC pins, stale integrity and separate retained decoder cases are neither skipped nor replaced with a modeled KUnit PASS.

The additional host regression compiles the **unchanged actual product** dormant decoder owner C/H plus codec C under GCC and Clang strict C23 high warnings, `-Werror`, ASan+UBSan. It separately compiles and **executes** baseline and two semantic mutants per compiler (missing old-reader release and missing late-reader release). A mutant is killed only by an observed semantic nonzero verdict **after** test cleanup releases the missed pin; build failures, sanitizer crashes and timeouts do not count.
