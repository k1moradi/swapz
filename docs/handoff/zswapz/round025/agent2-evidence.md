## Source-authentic STORE and original-page availability

The exact pinned `mm/zswap.c:zswap_store_page(struct folio *folio, long index, ..., struct zswap_pool *pool)` first allocates a real `zswap_entry`, calls `zswap_compress(folio, index, entry, pool)`, stores `pool->idx` before `xa_store(swap_zswap_tree(folio_swap_entry(folio,index)), swp_offset(...), entry, GFP_KERNEL)`, frees overwritten old entries with `zswap_entry_free(old)`, grabs the pool's real reference and only then initializes `entry->swpentry` and exposes the LRU node. `zswap_store()` documents `folio_test_locked(folio)` and `folio_test_swapcache(folio)`; it passes each page's `index` through to STORE. `zswap_compress()` already uses `sg_set_folio(..., index * PAGE_SIZE)` and `kmap_local_folio(folio,index*PAGE_SIZE)` for incompressible originals, so the original **plaintext 4096 bytes** exist at real STORE time and can be SHA-hashed independently of the compressed zpool allocation.

The pinned `include/crypto/sha2.h` declares `void sha256(const u8 *data, size_t len, u8 out[SHA256_DIGEST_SIZE])` and `SHA256_DIGEST_SIZE==32`. `include/linux/highmem.h` provides `kmap_local_folio/kunmap_local`. The original `struct zswap_entry` holds `swpentry`, `length`, `pool_idx`, `handle`, `objcg`, LRU state; the pinned `struct zswap_pool` has per-entry retained `idx`, immutable `tfm_name`, zsmalloc pool, refcount. **Neither type records an allocator-owned swap slot allocation/reuse epoch nor the original 4096 SHA.** The xarray pointer is NOT a slot allocator epoch. `mm/swapfile.c:swap_range_free()` calls `zswap_invalidate(type, offset, count)`, `mm/zswap.c:zswap_invalidate()` removes and frees the old entry, and `zswap_swapoff()` requires drained trees before their destruction. A future genuine proof must be minted by the MM slot allocator on actual allocation/reuse and remain tied to entry replacement/invalidation, pool ref, teardown and BIO clone/split lifetime. No such authenticated API exists in this pinned zswap source.

`zswap_writeback_entry()` still obtains a locked swap-cache folio, checks `entry==xa_load(tree,offset)` before dereferencing, **decompresses to exactly original 4096**, erases/frees the zpool entry, then performs original `__swap_writeout(&ctx,folio)` + `swap_write_submit(&ctx)`. Nothing here delivers a compressed LZ4 BIO to DM.
