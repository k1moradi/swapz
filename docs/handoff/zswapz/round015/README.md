## User's optimization goal — avoid zswap/swapz recompression competition

On pressure, *zswap* caches compressed swap pages in RAM and eventually evicts stored entries to backing swap. Existing Linux `zswap_writeback_entry()` typically **decompresses** the stored entry to a normal 4096-byte page before backing I/O; `swapz` can **recompress** it. The desired ideal is to transfer an **already-compressed, verified zswap payload** to swapz's backing extents while it remains losslessly decodable by the **actual originating zswap codec**, avoiding both unnecessary CPU stages and writing fewer physical bytes. However:

- Existing swapz **RAW = full uncompressed 4096-byte logical PAGE**, NOT a compressed-blob representation. Never write zswap-compressed bytes through RAW pretending they are a normal page. No (K)-page out-of-band metadata on physical SWAPSPACE2 media; all record/extent descriptors must remain **bounded volatile RAM**, and only payload bytes on disk after the protected SWAPSPACE2 first page.
- Current Phase A source has only semantic `ORDINARY_OR_UNKNOWN=0` vs `ZSWAP_STORED_WRITEBACK=1` origin, not compressed **representation**. Authentic origin alone **never** proves the compressed payload, its algorithm, compressor pool/dictionary, length, lifetime or ability to decode. A zswap entry can also contain full-size/uncompressed content; unknown/initial reject is **not** authorization to bypass compression.
- Direct compressed representation needs exact **logical 4096 bytes** on every upper READ; a separate versioned descriptor must validate `origin=stored_writeback`, independently authenticated `representation=compressed`, recognized zswap codec (e.g., LZ4 or ZSTD with actual matching decoder), payload length `1..3568` for today's bounded compressed extents, CRC/integrity and decode success to exactly 4096 bytes. Other sizes/codecs must use safe unchanged decompressed-page backing path, never truncate or silently reinterpret.
- Producer may not hand off a borrowed zpool pointer beyond zswap entry/pool lifetime; when sending an async BIO it must own an immutable bounded copy or independently reviewed pinned lifetime. The consumer needs verified split/clone association and no mixed-origin aggregates. No source-dependent disk metadata, new swap format, reclaim deadlock, unbounded allocations or loss of ordered generation/CRC/GC authority.
- No worker may enable **Phase B** generic zswap-origin forced RAW, an actual direct compressed writeback path, or live `dm-swapz` operation by inference. Phase B and the direct-compressed experiment remain **off by default** until producer+consumer are jointly source-compiled/tested against identical actual Linux and loaded authenticated stored-entry writeback/4096-byte readback has passed, including recovery/GC/teardown. Ordinary unknown traffic's existing path is invariant.
