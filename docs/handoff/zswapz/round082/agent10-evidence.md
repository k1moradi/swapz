The prior worker also exits before the caller's unreferenced task pointer is used by kthread_stop; pinned kernel/kthread.c explicitly requires task lifetime retention if threadfn can exit. These are source-level defects. New UML execution is required to establish full runtime repair.

The native test-only worker now publishes permanent `complete_all(&closer->returned)`, and task creation uses kthread_create, retains task_struct BEFORE wake_up_process, and balances put_task_struct after conditional join. The caller releases both possible leases before join via the exact shared helper `swapz_round080_release_decoder_leases` (late then primary, each guarded, first put error retained). Unexpected successful shutdown admission is still rejected and its acquired lease put. A real drain timeout is a **failure**: do not call kthread_stop on an unreturned uninterruptible waiter, or free worker-owned storage.
