## Memory and latency bounds

SWAPZ_MAX_RECORDS=64, SWAPZ_MAX_BLOCKS=4, SWAPZ_BULK_BLOCKS=64, SWAPZ_WORK_QUANTUM_BIOS=64, write pipeline depth 1. Constructor max_window is bounded by 64. Each batch_bytes and gc_bytes_store is 262144 bytes; the K=1 run uses engine.bulk_scratch (262144 bytes), not another independent bulk allocation (L14715-L14808). Preparation array has 64 slots each with a full raw and compressed-sized 4096-byte buffer (524288 bytes of payload capacity), plus struct metadata/alignment and lane scratch. These named payload stores alone total 1310720 bytes; not total driver memory, not a bound on all accepted DM BIOs, no claim that incoming FIFO is eight entries or that all buffers simultaneously contain distinct pages. Map is 20 bytes per logical page, with separate authority/GC sidecars and read caches/scratch. No new bytes proposed. No new memory reclaim.

Worst deliberate idle retention is configured cap (normally <=4ms, no retention at retain_ms=0); after service sample it is at most min(cap,max(20us,service/2)), unless no idle interval is active. Deadline is not an upper completion SLA: existing FIFO backlog, preparation, independent READ service adjustment, fences, GC, scheduling and lower service contribute. Lower device stalls lack a proven finite wall-clock completion bound in these rootless tests. Do not claim bounded worst end-to-end latency or infer latency from candidate synthetic ticks.
