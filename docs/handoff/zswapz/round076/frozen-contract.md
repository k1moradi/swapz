## Authentic cooperation and safety invariants

Actual [pinned original `mm/zswap.c`](https://github.com/torvalds/linux/blob/c339f4010dea8b0d754f84ace70cd1b089878ef8/mm/zswap.c) `zswap_writeback_entry()` around lines 994–1095 allocates locked swapcache folio, validates original XArray entry, calls `zswap_decompress(entry, folio)`, erases/frees original compressed entry and invokes standard `__swap_writeout`/`swap_write_submit` on **uncompressed** folio. Therefore a standard 4096-byte DM BIO does **not** carry a valid authenticated original compressed zswap payload. It would be a serious error to re-label compressed bytes as swapz conventional `RAW_4096`. Ordinary RAW_4096 always means the **complete 4096 original UNCOMPRESSED bytes**. A future distinct, source-authenticated, bounded `ORIGINAL_COMPRESSED_OPAQUE` path would require upstream original-stream lease and immutable owned copy **before source erase**, independently volatile original LZO1X/raw-LZ4 codec and pool/decoder generation, authenticated source swapcache folio/slot/epoch, upper-selected DM provenance, ordered data-only lower 4/8/16KiB WRITE+FUA/flush, full 4096 independently decoded cold read, GC/reader-pin lifetime, exactly-once real upper ACK. It is not available today; source custody and disk codec are distinct and synthetic witness bits cannot authenticate anything. Prefer proof-first and no new full integration code/loaded guest/physical tests yet.

Linux MM/zswap **exclusively** owns compressed RAM residence and natural pressure shrinker/eviction decision. swapz **exclusively** owns disk allocator, packer, deterministic padding and GC. No second swapz shrinker, memory-pressure event, zswap recompression or hidden fallback. Protect real physical SWAPSPACE2 first 4096 signature/UUID, partition table, exact fixed 20-byte volatile map and 4/8/16KiB extent bounds; no physical IO. `SOURCE_MAPPED_AUTHENTICATED=0`, `PHASE_A=BLOCKED`, `DIRECT_COMPRESSED_HANDOFF=DISABLED`, `FORCED_RAW_BYPASS=DISABLED`, import ACTIVE0, untouched production C/H.
