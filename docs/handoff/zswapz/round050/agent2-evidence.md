## Exact original original-source ownership boundary, swapoff ordering, and the first missing guarantee

**A. The counted acquisition itself is a valid original API only in a narrow source scope.** In pristine `mm/swapfile.c::folio_dup_swap(folio, NULL)`, original `folio->swap` identifies a CURRENT locked swapcache folio while the source owns its real folio lock; the original helper validates `folio_test_locked` and `folio_test_swapcache`, then increments actual swap-table count under the cluster spinlock. The original `swap_dup_entries_cluster` may unlock for `GFP_ATOMIC` extended-table allocation, re-lock/retry and on partial failure put all counts acquired in that batch. A successful external counted reference would need a separately owned, exactly-once put and a completion that cannot be lost. The alternative `swap_dup_entry_direct(swp_entry_t)` is *not* a constructor from a copied key: it requires the caller already own a genuine counted PTE/PTL- or shmem-protected reference and swap count >=1. Original `folio_put_swap(folio,NULL)` is legal only while that same genuine folio is still **locked and in swapcache**. Round049's guarded helper does precisely one immediate synchronous original `folio_dup_swap` / `folio_put_swap` pair on success, and no put on failure; it leaves **zero** extra counted refs on return. Its two original C refusal KUnit actually booted, but never performed a successful real swap-slot acquisition.

**B. A counted slot is not a universally deferred callback release contract.** Original `mm/swapfile.c::swap_put_entries_direct(swp_entry_t entry,int nr)` accepts a genuine preowned counted reference protected from owner replacement, *not* a copied type+offset/epoch. It is `void`: first calls `get_swap_device(entry)`, warns and immediately returns if that area cannot be live-acquired, otherwise decrements the original table count via `swap_put_entries_cluster(...,true)` and drops the area users ref. Unlike `folio_put_swap` the operation needs a fresh `percpu_ref_tryget_live(&si->users)` via `get_swap_device_info` and provides no returned release receipt. If the exact source counted ref and its owner are genuinely held throughout, **do not assert** that the area is inevitably killed first: original swapoff will normally need that outstanding use to go away. Conversely, the API has no guarantee of safe unconditional release from an independently expired *copied* slot after swapoff/reuse, and a copied sector, slot epoch or SHA is never a count owner.

**C. Decisive swapoff ordering and why a hidden count requires a real cancellation/drain protocol.** Original `mm/swapfile.c::SYSCALL_DEFINE1(swapoff)` removes the area from allocation and invokes `try_to_unuse(p->type)` **BEFORE** `percpu_ref_kill(&p->users)`, `synchronize_rcu`, waiting for `p->comp`, destroying extents, clearing `p->cluster_info` and `p->flags=0`. Original `try_to_unuse` visits shmem, page-table references via `unuse_mm`, and cached folios via `swap_cache_get_folio` / locked `folio_wait_writeback` / `folio_free_swap`; it **retries** while `swap_usage_in_pages(si)` stays nonzero, and may return `-EINTR` if interrupted. A newly retained external counted slot with no PTE, shmem object, current swapcache reference or guaranteed independent in-flight completion could leave slot usage nonzero yet not be discoverable by that built-in drain. It may cause repeated swapoff retries (or interruption/failure). The mere existence of a counted ref does not supply the missing external async callback, its exactly-once successful put, cancellation on error, or a cycle-free swapoff drain. The critical first guarantee missing is **a truly acquired external owned current slot reference with an explicit alive callback/abort owner that can release exactly once before unuse completes**, without waiting on a dependency blocked by swapoff/drain.

**D. The original source actually drops the preexisting protection before asynchronous submission.** In `mm/zswap.c::zswap_writeback_entry`, `get_swap_device` AREA users ref surrounds `__swap_cache_alloc_folio` only and is put before the current STORED `entry == xa_load(tree,offset)` recheck. After successful original decompression, `xa_erase`, `zswap_entry_free` and `folio_put` occur before `__swap_writeout` starts PG_writeback, **unlocks the original folio** and submits ordinary original 4096-byte uncompressed upper BIO. Original `mm/page_io.c::end_swap_bio_write` calls `bio_uninit` + `swap_write_end` and only ends folio writeback, with no external source-counted callback release or DM intake. `mm/swap_state.c::__swap_cache_do_del_folio` clears `folio->swap` and swapcache under cluster lock, and may free the slot if its real counted owners are zero. Thus a later use of a bare folio pointer or a type+offset copied before writeback is not protected by the prior folio lock, xarray check or internal BIO. There is **no original bridge** from a successfully duplicated slot count to a separately refcounted, cancelable, completion-owned external asynchronous object, and no real target/map/GC/dtr lease or correct original source bdev/nonlinear sector→current DM target-relative eight-sector translation.
