## Source truth and exact seam feasibility

The original `zswap_compress` at pinned `mm/zswap.c:856-936` stores the compressed result in a zsmalloc handle and writes `entry->length`; when compression fails, yields no data or produces at least 4096, it stores **the full original UNCOMPRESSED 4096-byte page** as a separate incompressible branch if writeback is permitted. `zswap_decompress` at 939-988 resolves the entry's pool, holds its compressor mutex, uses `zs_obj_read_sg_begin/end` and decompresses compressed bytes, while `entry->length == PAGE_SIZE` instead copies the entire raw uncompressed page. `zswap_writeback_entry` at 1005-1095 secures a swapcache folio, validates exact `entry == xa_load(tree, offset)` while locked, decompresses into the folio, then `xa_erase` and `zswap_entry_free` BEFORE ordinary `__swap_writeout` / `swap_write_submit`. **The ordinary DM WRITE receives the decompressed original page**, not any original compressed zpool stream.

The source verifier pins both original Git blobs and checks original source function and order anchors plus original `zswap_pool_get/put` `percpu_ref` and RCU-release path. It copies four exact original branch expressions from source into a generated header and independently compiles/evaluates those expressions in a guarded C host state model. That model does **not** compile or run original Linux `mm/zswap.c` or `mm/zsmalloc.c`; source assertions and hosted semantic simulations are distinct evidence.
